# Motokvest Bot

Telegram-бот для проведения мотоквестов. Игроки получают локации, добираются до точек, решают задания и получают обратную связь от инспектора — всё через Telegram.

[English version](README.md)

## Что умеет бот

- Три роли: **Игрок**, **Администратор**, **Инспектор**
- Администратор создаёт игровые сессии: выбирает игру, город, дату и место старта. Перед запуском отмечает, кто из зарегистрированных игроков пришёл
- Игрок получает локацию → добирается до точки → получает задание → отправляет ответ → при необходимости запрашивает подсказки → переходит к следующей точке
- Инспектор видит ответы игроков и принимает их или отклоняет
- Контент квеста описывается в JSON-файлах: локации, задания, подсказки, аудио, изображения
- JSON-схема валидирует файл с игрой при загрузке

## Архитектура

Три паттерна структурируют кодовую базу:

**State Machine** (`states/`)  
У каждого пользователя есть явное состояние (`UserState`) — значение enum, которое хранится в базе данных. Когда приходит сообщение, `UserStatesService` читает состояние, создаёт нужный объект состояния через `StateFactory` и вызывает его метод `handle()`. Каждый класс состояния отвечает за свою логику и переходы — никаких цепочек `if/else` в хендлерах.

**DI-контейнер** (`core/container.py`)  
Класс `Container` собирает все зависимости (бот, репозитории, сервисы) при запуске в одном месте. Ничего не инициализируется на уровне импортов. `get_container()` возвращает синглтон. Граф зависимостей явный и легко тестируется.

**Repository Pattern** (`database/repositories/`)  
Девять репозиториев оборачивают Peewee-модели и предоставляют методы с понятными именами. Бизнес-логика никогда не работает с ORM-запросами напрямую. В тестах репозитории работают с базой SQLite в памяти — моки слоя данных не нужны.

Ещё паттерны: декораторы для сквозной логики (`with_context`, `error_guard`, `log_exceptions`), DTO-объекты для передачи данных между слоями, compare-and-swap в `UserRepository` для защиты от гонок при многопоточном polling-е pyTelegramBotAPI.

## Структура проекта

```
motokvest_bot/
├── bot/                    # Точка входа (main.py)
├── cli/                    # CLI: загрузить игру, назначить админа, восстановить пользователя
├── config_data/            # Конфиг из .env + JSON-схема для файлов игр
├── core/
│   ├── container.py        # DI-контейнер
│   ├── dto/                # Data Transfer Objects
│   ├── enums/              # UserState, UserRole, SessionState, ...
│   └── utils/              # Вспомогательные функции валидации
├── database/
│   ├── models/             # Peewee-модели (User, GameSession, PointProgress, ...)
│   └── repositories/       # 9 репозиториев (BaseRepository + доменные)
├── decorators/             # with_context, error_guard, log_exceptions
├── games_data/             # Контент квестов в JSON + медиафайлы
├── handlers/               # Роутеры сообщений и callback-ов
├── presenters/             # Построители текстов и клавиатур
├── services/               # Бизнес-логика (AdminHandler, InspectorHandler, UIService, ...)
├── states/                 # State Machine: BaseUserState, StateFactory, классы состояний
└── tests/                  # pytest: 119 тестов в 9 файлах
```

## Установка

**1. Клонировать и установить зависимости**

```bash
git clone https://github.com/pybyOx/motoquest_bot.git
cd motoquest_bot
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

**2. Настроить переменные окружения**

Скопируй `.env.template` в `.env` и заполни значения:

```
BOT_TOKEN=токен_бота
MAIN_ADMIN_ID=telegram_user_id
ADMIN_IDS=id1,id2         # через запятую, можно оставить пустым
INSPECTOR_ID=telegram_user_id
```

**3. Загрузить данные игры**

```bash
python -m cli.create_game games_data/way_of_the_dragon/game_dragon.json
```

Формат JSON и инструкция по созданию своей игры — в `games_data/README.md`.

**4. Назначить администратора**

```bash
python -m cli.set_admin <telegram_user_id>
```

**5. Запустить бота**

```bash
python -m bot.main
```

## Запуск тестов

```bash
pytest
```

Все тесты используют SQLite в памяти и не требуют внешних сервисов.

## Роли

| Роль | Как получить | Возможности |
|---|---|---|
| Игрок | `/start` → регистрация | Проходить точки, отправлять ответы, запрашивать подсказки |
| Администратор | Назначается через CLI | Создавать/управлять игровыми сессиями, отмечать присутствие, запускать игру |
| Инспектор | Задаётся через `INSPECTOR_ID` в `.env` | Проверять и принимать ответы игроков |
